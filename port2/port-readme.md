# Porting ex/vi 3.7 (VAX) to Modern Linux

## Source

The original source is ex/vi version 3.7 from the VAX distribution
(`/home/pjdennis/research/vi/vax/`), circa 1981, by Bill Joy and
Mark Horton at UC Berkeley.

## Target

Modern Linux (x86-64) with GCC, targeting xterm-compatible terminals
(xterm, gnome-terminal, Windows Terminal via WSL, etc.).

## Build

```
cd vi/
make        # produces ./vi binary
make clean  # removes objects and binary
```

The Makefile defines `-DVMUNIX -DUSG -DTABS=8 -DSIGTSTP` and
suppresses numerous K&R-era warnings (`-Wno-implicit-function-declaration`,
`-Wno-implicit-int`, etc.). No external libraries are required (no
curses/ncurses/terminfo).

## Architecture of the Port

The port follows a "minimal changes" philosophy: keep the original C
source as close to the original as possible, using header-level shims
and a small number of new files to bridge the gap.

### New Files (not in the original)

| File | Purpose |
|------|---------|
| `vi_compat.h` | Compatibility layer: maps old USG termio to POSIX termios, `bcopy` to `memmove`, provides `<stdint.h>`, `<unistd.h>`, etc. |
| `vi_term.h` | Declares all terminfo capability variables (string and boolean) as `extern`, plus prototypes for `vi_setupterm()`, `vi_tparm()`, `vi_tputs()`. Macros redirect the original `setupterm`/`tparm`/`tputs`/`resetterm`/`saveterm`/`fixterm` names. |
| `vi_term.c` | Hardcoded ANSI/xterm escape sequences for all capabilities. Implements `vi_setupterm()` (reads window size via `TIOCGWINSZ`, installs `SIGWINCH` handler), `vi_tparm()` (formats parameterized capabilities by pointer identity), `vi_tputs()` (outputs strings, no padding delays). |
| `vi_mem.h` | Declares `vi_mem_init()` and `vi_morelines()`. |
| `vi_mem.c` | Replaces `sbrk()`/`brk()` memory management with `malloc()`/`realloc()`. Manages the line pointer array dynamically; adjusts all global `line*` pointers when `realloc` moves the block. |
| `Makefile` | New Makefile for the ported build. |

### Ported Files (from the original, with modifications)

All 26 original C source files plus all original header files
(`ex.h`, `ex_argv.h`, `ex_re.h`, `ex_temp.h`, `ex_tty.h`,
`ex_tune.h`, `ex_vars.h`, `ex_vis.h`) were copied and modified.

K&R function definitions are preserved throughout.

## Systematic Transformations

### 1. Preprocessor conditionals resolved

The original code has many `#ifdef`/`#ifndef` blocks for portability
across V6, V7, USG (System III/V), BSD, VMUNIX, etc. We resolved
these to keep only the paths that apply:

- **VMUNIX** (`#ifdef VMUNIX`): Always active. Keeps in-core temp
  file buffering, `char*` error message pointers (not file offsets).
- **USG** (`#ifdef USG`): Always active. Keeps `struct termio`-style
  tty handling (which we then map to `termios`), USG `tty.c_cc[]`
  constants (`VERASE`, `VKILL`, `VQUIT`, `VSTART`, `VSTOP`), and
  `c_iflag`/`c_oflag`/`c_lflag` bit manipulation.
- **Non-USG / BSD paths** (`#ifndef USG`): Removed. These used
  `gtty()`/`stty()`, `sg_ospeed`, `struct tchars`, `TIOCGETC`,
  `TIOCSETC`, `TIOCGLTC`, `TIOCSLTC`, `TIOCGETD` — none of which
  exist on modern Linux.
- **SIGTSTP** (`#ifdef SIGTSTP`): Kept (Linux supports job control).
- **NTTYDISC** (`#ifdef NTTYDISC`): Removed (BSD line discipline).
- **CBREAK** (`#ifndef CBREAK`): Removed (we always have CBREAK).
- **STDIO** (`#ifdef STDIO`): Removed (not defined).
- **lint** (`#ifdef lint`): Removed.
- **mbb** (`#ifdef mbb`): Removed (C/70 with 10-bit byte).
- **u370** (`#ifdef u370`): Removed (IBM mainframe).

### 2. Terminal interface replaced

The original used `setupterm()`/`tparm()`/`tputs()` from
libcurses/libterminfo with runtime terminal description lookup.
Replaced entirely with `vi_term.h`/`vi_term.c` which hardcodes
ANSI/xterm sequences. The original `term.h` (generated by terminfo
tools) is replaced by `vi_term.h`.

Capability variables use the same names as the original terminfo
interface (`cursor_address`, `insert_line`, `auto_right_margin`, etc.)
and are declared as `extern` globals, so the original code references
them without modification.

The `tparm` macro uses a variadic wrapper to handle both 2-argument
and 3-argument call sites:
```c
#define VI_TPARM_3(a,b,c,...) vi_tparm(a,b,c)
#define tparm(...) VI_TPARM_3(__VA_ARGS__, 0, 0)
```

### 3. Memory management replaced

Original used `sbrk()`/`brk()` to grow the data segment for line
pointers. Replaced with `vi_mem.c` which uses `malloc()`/`realloc()`.
In `ex.c`, the original `fendcore = (line *) sbrk(0); endcore = fendcore - 2;`
is replaced with `vi_mem_init()`. All calls to `morelines()` in the
original code are changed to `vi_morelines()`.

### 4. TTY ioctl calls replaced

- `ioctl(fd, TCGETA, &tty)` replaced with `tcgetattr(fd, &tty)`
- `ioctl(fd, TCSETAW, &tty)` replaced with `tcsetattr(fd, TCSADRAIN, &tty)`
- `tty.c_cflag & CBAUD` replaced with `cfgetospeed(&tty)`
- `SGTTY` typedef changed from `struct termio` to `struct termios`

### 5. CTRL() macro fixed

The original macro `#define CTRL(c) ('c' & 037)` (stringizing the
argument) was already corrected in the ported `ex.h` to
`#define CTRL(c) ((c) & 037)`. All call sites were updated from
`CTRL(d)` to `CTRL('d')`, `CTRL(v)` to `CTRL('v')`, etc.

### 6. `inline` keyword conflict

The C99 reserved keyword `inline` was used as a variable/parameter
name in `ex_get.c` and `ex_addr.c`. Renamed to `inputline` throughout.

### 7. `getline` name clash

POSIX `getline()` from `<stdio.h>` clashes with vi's own `getline(tl)`
(which reads a line from the temp file). Resolved by adding
`#define getline __posix_getline` before all `#include <stdio.h>`
directives in `ex.h`, then `#undef getline` after, so vi's own
`getline` is used via implicit declaration.

### 8. `line` type name clash

The `checkmodeline()` function in `ex_io.c` had a parameter named
`line` which clashed with the `line` typedef. Renamed to `l`.

### 9. Signal handling

- `SIGEMT`: Does not exist on Linux. The `#ifdef SIGEMT` guard was
  added in `ex.c` (the only file that references it). `onemt()` in
  `ex_subr.c` was made a no-op.
- Signal handlers remain K&R-style `int` return type (suppressed via
  `-Wno-incompatible-pointer-types`).

### 10. Removed obsolete code

- `sbrk()`/`brk()` calls (replaced by `vi_mem.c`)
- `erpath`/`erfile` error message file mechanism (VMUNIX uses
  in-memory strings)
- `std_errlist[]` array in `ex_subr.c` (replaced with `strerror()`)
- Custom `exit()` function (modern libc provides it)
- `read()`/`write()` forward declarations in `ex_temp.c` (provided
  by `<unistd.h>`)
- AT&T copyright headers (UC Berkeley headers retained)

### 11. Other per-file fixes

- `ex_cmdsub.c`: Added `static splitit();` forward declaration to
  resolve static-after-implicit error.
- `ex_io.c`: `#define index strchr` / `#define rindex strrchr` block
  (under `#ifdef USG`) kept for `checkmodeline()`.
- `ex_temp.c`: `pagrnd` macro changed from `((int)a)` to
  `((uintptr_t)(a))` for 64-bit pointer safety.
- `ex_unix.c`: `#ifndef VFORK` conditional resolved to plain `fork()`.
- `ex_tty.c`: `IUCLC` guarded with `#ifdef` (not available on all
  Linux configurations). `TABDLY`/`TAB3`/`XTABS` guarded with
  cascading `#ifdef`.

## Known Limitations / Future Work

### Warnings

The build produces numerous warnings (suppressed via `-Wno-*` flags)
due to K&R coding style:
- Implicit function declarations (functions used before declared)
- Implicit `int` return types
- Missing return values
- Pointer/int conversions (original assumes `sizeof(int) == sizeof(char*)`)

These are cosmetic for now. Converting all functions to ANSI prototypes
would be a large but straightforward mechanical task.

### 64-bit pointer issues

The original code freely casts between `int` and pointers. On 64-bit
Linux, `sizeof(int) == 4` but `sizeof(void*) == 8`. The
`-Wno-pointer-to-int-cast` and `-Wno-int-to-pointer-cast` flags
suppress these. The `line` type is `typedef int line` — line values
are temp file block indices, not pointers, so they fit in `int`. The
`pagrnd` macro in `ex_temp.c` was fixed to use `uintptr_t`. Other
pointer-to-int casts may cause issues with files larger than the
temp file buffer can index.

### Terminal capabilities

All capabilities are hardcoded for ANSI/xterm. The `vi_setupterm()`
function ignores the terminal type argument. This works for any
xterm-compatible terminal but will not work for truly non-ANSI
terminals. To support other terminals, `vi_term.c` would need to be
extended (or replaced with actual terminfo lookups via ncurses).

The `vi_tparm()` function identifies capabilities by pointer identity
(e.g., `if (cap == cursor_address)`). This works because the code
always passes the global variable directly. If code were to copy a
capability string and pass the copy, the identity check would fail.

### Missing features

- No EXINIT/exrc environment variable processing has been tested.
- The modeline feature (`checkmodeline`) is present but untested.
- Tag file support is present but untested.
- The `preserve` command (crash recovery) is present but the
  preserve directory setup has not been verified.

### Adding new terminal capabilities

If you encounter an undeclared terminal capability name at compile
time, add it in three places:
1. `vi_term.h` — `extern` declaration (use `char*` for string
   capabilities, `int` for boolean/numeric)
2. `vi_term.c` — definition with appropriate ANSI escape sequence
   (or `NULL`/`0` if the capability doesn't apply)
3. If the capability is parameterized (contains `%d` in its escape
   sequence), add a case in `vi_tparm()` in `vi_term.c`

### Original code comments

The ported files use comment markers to document what was changed
from the original source. This makes it possible to understand the
original code and to strip the annotations mechanically.

**Marker formats:**

1. **`/* ORIG: ... */`** — Single-line note showing the original code
   or construct that was replaced:
   ```c
   /* ORIG: #define CBREAK xxxxx */
   #define CBREAK 1
   ```

2. **`/* ORIG_BEGIN: description */` ... `/* ORIG_END */`** — Brackets
   a section where the original had conditional compilation or other
   code that was resolved/simplified. The removed paths may appear as
   commented-out code between the markers:
   ```c
   /* ORIG_BEGIN: VMUNIX conditional for LBLKS/HBLKS */
   /* #ifndef VMUNIX            */
   /* #define LBLKS      125    */
   /* #define HBLKS      1      */
   /* #else                     */
   /* ORIG_END */
   #define LBLKS      900
   #define HBLKS      2
   ```

3. **`/* ORIG_REMOVED: description */`** — Marks code that was
   entirely removed. A single-line form for small removals:
   ```c
   /* ORIG_REMOVED: char *tparm(); - provided by vi_term.h */
   ```
   A multi-line block form uses `:ORIG_REMOVED` as the closing marker:
   ```c
   /* ORIG_REMOVED: std_errlist[] array - using strerror() instead */
   /* :ORIG_REMOVED */
   ```

4. **`* ORIG_BEGIN:` / `* ORIG_END` inside block comments** — Same
   semantics as the `/* */` form, but embedded in an existing block
   comment:
   ```c
   /*
    * ORIG_BEGIN: USG CBREAK simulation
    * The original defined CBREAK to a garbage value under USG...
    */
   ```

5. **`PORT_NOTE:`** — Any comment text added during the port that is
   not documenting removed/changed original code via ORIG markers.
   This covers explanatory notes, new section headings, replaced
   copyright headers, added forward declarations, and clarifications
   appended to original comments. PORT_NOTE appears in several forms:

   As a standalone comment line:
   ```c
   /* PORT_NOTE: Hide POSIX getline() which clashes with vi's own getline(tl) */
   #define getline __posix_getline
   ```
   As a trailing comment on a code line:
   ```c
   static splitit(); /* PORT_NOTE: forward declaration to resolve static-after-implicit error */
   ```
   Inside a block comment (with `*` prefix):
   ```c
   /*
    * PORT_NOTE: Memory management (replaces sbrk/brk)
    */
   ```
   As an inline annotation appended to an original comment:
   ```c
    * Capabilities from termcap/terminfo  PORT_NOTE: added /terminfo
   ```

**Scope rules:**
- `PORT_NOTE:` is used only for freestanding port commentary.
- Comments inside `ORIG_REMOVED` / `:ORIG_REMOVED` blocks or between
  `ORIG_BEGIN` / `ORIG_END` markers do NOT need `PORT_NOTE:` — the
  enclosing ORIG markers already identify the content as port-related.
- `ORIG_REMOVED` is used when original code (e.g., an AT&T copyright
  header) was replaced; the replacement text that follows is unmarked.

All comments that do not contain `ORIG:`, `ORIG_BEGIN`, `ORIG_END`,
`ORIG_REMOVED`, `:ORIG_REMOVED`, or `PORT_NOTE:` — and are not
inside an ORIG block — are original comments from the source.

**Stripping all port annotations:**

To produce clean files with no porting annotations:

```sh
# Remove all ORIG and PORT_NOTE comment lines
sed -i \
  -e '/\/\* ORIG:/d' \
  -e '/\/\* ORIG_REMOVED:/d' \
  -e '/\/\* ORIG_BEGIN:/d' \
  -e '/\/\* ORIG_END/d' \
  -e '/\/\* :ORIG_REMOVED/d' \
  -e '/\/\* PORT_NOTE:/d' \
  *.c *.h

# Remove ORIG/PORT_NOTE markers inside block comments
sed -i \
  -e '/^ \* ORIG_BEGIN:/d' \
  -e '/^ \* ORIG_END/d' \
  -e '/^ \* ORIG:/d' \
  -e '/^ \* PORT_NOTE:/d' \
  *.c *.h

# Strip trailing PORT_NOTE comments from code lines
sed -i 's| */\* PORT_NOTE:.*\*/||' *.c *.h

# Remove commented-out original code between ORIG_BEGIN/ORIG_END
# (lines that are just /* ... */ with original code inside)
# These must be reviewed manually since not all such comments are ORIG artifacts.
```

Note: the block-comment-embedded form (`* ORIG_BEGIN` inside a `/* */`
block) cannot be fully stripped by line-oriented sed since removing
those lines may leave malformed block comments. Review those ~8 files
manually after stripping.

### Converting K&R to ANSI prototypes

If you want to modernize function definitions:
- Original: `foo(a, b) int a; char *b; { ... }`
- Modern: `int foo(int a, char *b) { ... }`
- Be careful with functions that return non-int (the original relies
  on implicit `int` return everywhere)
- Signal handlers should return `void`, not `int`
- Watch for parameter names that clash with typedefs (e.g., `line`)
